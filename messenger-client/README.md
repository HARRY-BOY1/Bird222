# مراسِل — تطبيق PWA للمحادثات

واجهة عربية RTL، mobile-first، مبنية بـ HTML وCSS وJavaScript عاديين من دون framework أو build step. تستخدم خادم المراسلة في `../messenger-server/`، وتحمل نسخة Socket.IO client نفسها من الخادم.

## تشغيل الخادم والواجهة محلياً

1. شغّل الخادم من نافذة طرفية:

   ```powershell
   cd ..\messenger-server
   npm start
   ```

2. في نافذة ثانية شغّل واجهة PWA:

   ```powershell
   cd ..\messenger-client
   npm start
   ```

3. افتح `http://localhost:4173`، وسجّل حساباً أو ادخل بحساب موجود.

يخدم `npm start` ملفات الواجهة على `0.0.0.0:4173` (افتراضياً) باستخدام خادم Node صغير من دون حزم إضافية. ويمكن تغيير `PORT` أو `HOST` عند الحاجة.

## إعداد عنوان الخادم

غيّر **`SERVER_URL` في `config.js` فقط**، ويُشتق منه عنوان API وScript Socket.IO:

```js
const SERVER_URL = 'http://localhost:3001';
```

لا ترسل JWT إلى عنوان غير موثوق؛ عميل Socket.IO يحمّل أيضاً من الخادم المحدد. service worker لا يخزّن `/api/` أو `/socket.io/` أو `/health`.

## النشر

- **Render (الخادم):** `messenger-server/render.yaml` جاهز. أضف `NODE_ENV=production`، `JWT_SECRET` (32+ محرفاً)، `CORS_ORIGIN`، و`DB_PATH=./data/app.db` من لوحة Render، وأضف قرصاً دائماً على `./data`.
- **Netlify (الواجهة):** `messenger-client/netlify.toml` ينشر المجلد من دون بناء. غيّر `SERVER_URL` في `config.js` إلى عنوان الخادم، وأضف أصل النشر إلى `CORS_ORIGIN` في الخادم.

## اختبارها على الهاتف (Wi‑Fi نفسه)

عنوان الكمبيوتر في الشبكة المحلية هنا هو `192.168.0.14`.

1. في `messenger-client/config.js`، غيّر `localhost` في `SERVER_URL` إلى `192.168.0.14`. عنوان الشبكة المحلية الحالي لهذا الكمبيوتر `192.168.0.14`.
2. في `messenger-server/.env` أضف أصل الواجهة إلى `CORS_ORIGIN` مع الإبقاء على الأصل المحلي إن كنت تستخدمه أيضاً:

   ```env
   CORS_ORIGIN=http://localhost:4173,http://192.168.0.14:4173
   ```

   هذا **تغيير بإعدادات البيئة فقط**، وليس تعديلًا لكود الخادم.
3. أعد تشغيل خادم الرسائل. شغّل خادم العميل بـ `npm start` مع الاستماع إلى `0.0.0.0`، واترك نافذتي الطرفية تعملان.
4. اسمح لـ Node.js بالاتصالات الواردة في Windows Firewall إذا ظهرت مطالبة، وتأكد من أن الشبكة تسمح للأجهزة بالتواصل.
5. افتح على الهاتف `http://192.168.0.14:4173`، وسجّل حساباً. أضف PWA إلى الشاشة الرئيسية من قائمة المتصفح.

> **مهم لأمان PWA:** متصفحات الهاتف تتطلب HTTPS لتفعيل service worker والتثبيت، والاستثناء الآمن عادةً هو `localhost` فقط. استخدام `http://<LAN-IP>:4173` قد يعرض الصفحة لكنه **لن يضمن تثبيت PWA أو offline service worker**. لاستخدام PWA بشكل كامل على الهاتف، استضف الواجهة والخادم عبر HTTPS (مثلاً reverse proxy أو نفق HTTPS موثوق). كذلك الرمز في `localStorage` مكشوف لأي JavaScript خبيث يعمل على نفس الأصل؛ هذا تخزين محلي مقصود حسب المتطلب، فاحمِ الأصل وفضّل HTTPS.

## ما توفره الواجهة

- تسجيل الدخول وإنشاء الحساب، مع استعادة الجلسة من JWT المخزّن.
- قائمة جهات الاتصال، معاينات أحدث الرسائل، العدّ غير المقروء والحضور.
- محادثة فورية، فقاعات رسائل، أوقات، حالات sent/delivered/read، ومؤشر كتابة.
- مكالمات صوتية ومرئية عبر WebRTC مع قبول/رفض، كتم الميكروفون، إيقاف الكاميرا، إنهاء المكالمة ومؤقت للمدة. تحتاج HTTPS وإذن الميكروفون/الكاميرا، وقد تحتاج بعض الشبكات إلى خادم TURN إضافي.
- إضافة مستخدم من شاشة البحث، وتحميل سجل أقدم عند الصعود إلى أعلى المحادثة.
- اتصال Socket.IO تلقائي بإعادة الاتصال، ووضع فاتح/داكن يتبع إعداد النظام مع زر تبديل.
- manifest وأيقونات 192/512 وخدمة worker تخزن app shell فقط، ولا تعترض API أو Socket.IO.
- رسائل المستخدم تُعرض بـ `textContent`، لا `innerHTML`.

### المكالمات عبر شبكات مختلفة

تستخدم المكالمات WebRTC مع STUN، وتدعم خادم TURN عبر المتغيرات `TURN_URL` و`TURN_USER` و`TURN_PASS` في `index.html` (يمكن ضبطها أيضاً من `config.js`). يمكن الحصول على TURN مجاني/رخيص من مزودين مثل OpenRelay أو metered.ca أو coturn مستضاف ذاتياً. **بدون TURN لا يمكن ضمان نجاح المكالمات بين شبكتين مختلفتين**؛ يعتمد ذلك على نوع NAT/firewall. الرنين والقبول والرفض والإنهاء وتسجيل المكالمات وعرض الكاميرا المحلية تعمل، لكن وسائط الصوت/الفيديو الفعلية بين شبكتين قد تحتاج TURN.

### حدود متعلقة بواجهة الخادم الحالية

- يوفر الخادم قائمة جهات الاتصال فقط، وليس جميع المستخدمين المتصلين؛ لذلك تظهر محادثات جهات الاتصال المضافة.
- لا توجد API لإزالة جهة اتصال أو تاريخ مستخدمين متصلين قبل اتصال العميل، فتتحدث الحالة عند أحداث الحضور بعد الاتصال.
- Socket.IO يرسل تحديث `message:status` للمرسل فقط؛ لا يوفر API لاسترجاع حالة كل رسالة مستقلة. تُعرض تحديثات الحالة أثناء بقاء جلسة الاتصال، وتُحفظ معاينة آخر رسالة محلياً.
- ظهور اسم المجموعة أو المحادثة لا يعني تشفيراً طرفياً؛ الاتصال محمي بـ JWT فقط.

## الاختبار

```powershell
npm test
```

يفحص الاختبار ملفات PWA، والتوجيه RTL، واستثناء API من التخزين، وعرض الرسائل الآمن، والأيقونات. لتشغيل الواجهة:

```powershell
npm start
```

ثم افتح الواجهة بالمتصفح. لتجربة الحسابين، شغّل خادم المراسلة وشغّل `npm run demo` في مجلد `messenger-server`، أو سجّل مستخدمين من نافذتين خاصتين وأضف كل حساب جهة اتصال للآخر.
